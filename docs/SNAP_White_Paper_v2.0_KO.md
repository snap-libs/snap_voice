## 1. 개요

### 1.1. 왜 SNAP이 필요한가?

#### ① TTS 파이프라인의 오류 전파 (Cascading Error Propagation)
음성합성(TTS) 시스템은 일반적으로 **텍스트 정규화(TN) → 음운 변환(G2P) → 음향 모델(Acoustic Model) → 보코더(Vocoder)**의 순차 파이프라인 구조를 따릅니다.  
이 구조에서 프론트엔드(TN/G2P) 단계의 오독이나 비표준 발음 변환은 다운스트림 음향 모델로 그대로 전파되며, 이후 단계에서 이를 자체적으로 보정할 수 없습니다. 따라서 텍스트 전처리 단계의 정확도는 최종 합성 음성의 명료도와 직결됩니다.

전 세계의 모든 자연어는 정도의 차이가 있을 뿐, **표기 형태는 같지만 문맥과 화용적 의미에 따라 발음이 완전히 달라지는 '발음의 모호성(Phonological Ambiguity)'**을 본질적으로 내포하고 있습니다:
* **한국어**: 동일한 표기라도 문맥에 따라 발음이 갈리는 동철이음이의어  
  - `"희생의 대가를 치르다"` [대까] (비용·희생) vs `"서예의 대가를 만나다"` [대가] (거장·권위자)
* **영어**: 문맥과 시제에 따라 음소가 달라지는 이형태어(Heteronym)  
  - `"I read books every day"` [riːd] (현재 시제) vs `"I read the book yesterday"` [rɛd] (과거 시제)
* **일본어**: 단어의 결합과 의미 맥락에 따라 음독(音読み)과 훈독(訓読み)이 갈리는 한자 표기  
  - `"一日"` [ついたち (초하루/1일)] vs [いちにち (하루 동안)]
* **공통 수치 및 특수 서식**: 전후 맥락에 따라 해석 체계가 완전히 달라지는 복합 기호  
  - `"10:12"`: `"현재 시각은 10:12입니다"` **[열 시 십이 분]** (시각) vs `"경기 결과 10:12로 끝났다"` **[십 대 십이]** (점수)

물론 실제 일상 대화나 텍스트 코퍼스에서 이러한 모호성을 지닌 문장의 비중은 전체의 약 **3%~15%** 안팎으로 통계적으로는 비교적 작은 편입니다. 따라서 복잡한 문맥 처리 없이 단순 정규표현식(Regex)이나 소규모 사전, 기초적인 규칙만 적용하더라도 전체 문장의 85%~97%는 그럴듯하게 발음할 수 있습니다.

**문제는 간혹 발생하더라도 지속적으로 터져 나오는 이 소수의 발음 오류가 음향 모델로 여과 없이 직결된다는 점입니다.**  
최근 TTS 기술은 딥러닝 음향 모델과 신경망 보코더의 비약적인 발전에 힘입어 사람의 고유한 음색, 자연스러운 억양, 섬세한 호흡과 감정까지 완벽에 가깝게 재현하는 수준에 도달했습니다. 그러나 아무리 뛰어난 음향 모델이라 하더라도, **읽어야 할 원고(전처리 결과물) 자체에 오독이나 어색한 발음이 섞여 있다면 최첨단 합성 기술 전체가 무색해지고 맙니다.** 즉, 현재 시점에서 고품질 TTS의 최종 완성도는 음향 모델 자체보다 **프론트엔드 전처리의 무결성**에 의해 크게 좌우되는 형국입니다.

이 때문에 오디오북, 방송 더빙, AICC 등 품질이 엄격해야 하는 상용 음성 제작 현장에서는 TTS 텍스트 전처리를 완전히 자동화하지 못하고 있습니다. 작업자가 사전에 대본을 전수 검수하여 오독이 예상되는 단어를 소리 나는 한글로 직접 고쳐 쓰거나(Manual Overriding), 수작업으로 단어 사전을 등록하고 SSML 태그를 일일이 달아주는 **'휴먼 인 더 루프(Human-in-the-loop)' 검수 작업이 필수적인 비용과 시간 병목**으로 작용하고 있습니다.

더욱 큰 문제는 사람이 사전에 개입할 수 없는 **'실시간 대화형 AI(Interactive Voice AI, LLM-to-Speech)'나 실시간 AICC 환경**입니다. 이러한 환경에서는 사후 수작업 검수가 물리적으로 불가능하므로, 프론트엔드의 미세한 전처리 오류가 최종 사용자에게 여과 없이 노출되어 대화 경험을 심각하게 훼손합니다.

#### ② 기존 전처리 방식의 구조적 한계와 트레이드오프

음성 프론트엔드 분야에서 주로 활용되어 온 기존 방식들은 각자의 뚜렷한 장점과 함께, 문맥성 발음 변환에 있어 구조적 한계를 지니고 있습니다:

* **1. 규칙 및 FST(유한상태변환기) 기반 방식**:
  * **대표 패키지 및 도구**: OpenFST / Thrax (Google), espeak-ng, g2pK, Misaki, Gruut 등
  * **원리**: 사전에 정의된 정규표현식(Regex), 치환 규칙 테이블, 혹은 정규 문법을 컴파일한 유한상태변환기(FST, Finite State Transducer)를 통해 표면 문자열을 선형 매칭하여 변환합니다.
  * **장점**: 연산량이 매우 적고 처리 속도가 마이크로초(µs) 단위로 극도로 빠르며, 결과가 100% 결정론적(Deterministic)이어서 시스템 동작 예측과 관리가 용이합니다.
  * **한계**: 표면 문자열의 정적 패턴에만 의존하므로, 단어 주변의 복합적인 문맥이나 문장 전체의 화용적 의미에 따라 발음이 갈리는 어휘에는 반응하기 어렵습니다. 이러한 예외를 규칙으로만 처리하려 할수록 다단계 조건문이 지나치게 복잡해지고 규칙 간 상호 충돌이 발생합니다.

* **2. 통계 기반 형태소 분석 및 동적 계획법(Lattice DP / Viterbi) 방식**:
  * **대표 패키지 및 도구**: MeCab / MeCab-ko, Kuromoji, Sudachi, Jieba, Phonetisaurus, KoNLPy 등
  * **원리**: 사전을 기반으로 문장에서 분절 가능한 모든 형태소 후보군을 노드로 배치하여 단어 격자(Word Lattice)를 생성한 뒤, 각 형태소의 출현 빈도(단어 발생 비용)와 인접 품사 간 전이 확률(Bi-gram/Tri-gram 연결 비용)을 바탕으로 동적 계획법(DP, Viterbi 알고리즘)을 수행하여 누적 비용이 가장 낮은 최적의 형태소 경로를 선택합니다(HMM, Linear-chain CRF 등).
  * **장점**: 순수 규칙 방식과 달리, 인접 형태소 품사 간의 결합 패턴을 확률적으로 고려하여 어휘의 분절 경계와 기본 품사를 유연하고 안정적으로 판별합니다.
  * **한계**:
    1. **로컬 마르코프 가정(Markov Assumption)의 한계**: 주로 인접한 1~2개 품사 전이 확률에만 의존하므로, 문장 전체에 걸친 장거리 의미 의존성(Long-range dependency)을 반영하지 못합니다.
    2. **동일 품사(POS) 내 의미 변별 불가**: 통계적 DP의 목적 함수는 '최적의 품사 시퀀스'를 찾는 것입니다. 그러나 동일한 철자를 가진 동철이음이의어는 문맥이 달라도 앞뒤 결합 품사 열이 완전히 동일한 경우가 많습니다. 품사 전이 비용이 같기 때문에 Lattice DP는 의미 차이에 따른 경음화나 음운 변동 여부를 구조적으로 구별하기 어렵습니다.
    3. **수사·단위의 문맥 분류 한계**: 아라비아 숫자와 단위명사의 결합 역시 품사 태그 구조가 동일하므로, 문장 전체의 술어 맥락에 따라 고유어 수사로 읽을지 한자어 수사로 읽을지 구별해 내지 못합니다.

* **3. 신경망 Seq2Seq / 번역 모델 기반 방식**:
  * **대표 패키지 및 도구**: NVIDIA NeMo (Neural TN/G2P), Google Transformer-TN, Deep-Phonemizer, g2pE 등
  * **원리**: 텍스트 시퀀스를 입력받아 정규화된 텍스트나 음소열을 직접 생성(Generation)하는 엔드투엔드 인코더-디코더(RNN, Transformer) 번역 모델 구조입니다.
  * **장점**: 어텐션(Attention) 메커니즘을 통해 문장 전체의 넓은 문맥을 유연하게 반영합니다.
  * **한계**: 생성형 모델 특유의 **단어 누락, 환각(Hallucination), 임의 치환 오류**가 발생할 위험이 있어, 한 글자의 오독도 치명적인 음성합성 시스템에서 절대적인 출력 무결성을 보장하기 어렵습니다.

* **4. 대형 언어 모델 (LLM) 기반 방식**:
  * **대표 패키지 및 파이프라인**: NeMo Canary, ChatTTS 텍스트 프론트엔드, 파운데이션 모델(GPT-4o, Claude 등) 기반 Few-Shot/프롬프트 파이프라인
  * **원리**: 대규모 사전학습 언어 모델의 추론 능력을 활용하여 문맥을 이해하고 정규화된 표현을 생성합니다.
  * **장점**: 고차원 의미 이해도와 광범위한 상식을 바탕으로 복잡하고 비정형적인 문맥을 가장 유연하게 해석합니다.
  * **한계**: 대규모 파라미터 구조상 **높은 지연 시간(Latency)과 컴퓨팅 비용**이 발생하여, 실시간 스트리밍 음성합성이나 대화형 AI 환경에서 요구되는 밀리초(ms) 단위의 응답성과 처리량을 달성하기 어렵습니다.

#### ③ SNAP의 해결 접근법: 왜 생성형이 아닌 BERT인가?

기존 전처리 방식들이 직면한 딜레마를 극복하기 위해, SNAP은 **"신경망의 문맥·의미 정보 추출"**과 **"결정론적 룰 엔진의 안전한 최종 제어"**를 명확히 분리한 하이브리드 아키텍처를 채택했습니다.

이 설계의 핵심은 **"음성 프론트엔드에서 신경망에 요구되는 역할은 텍스트를 새롭게 지어내는 '생성(Generation)'이 아니라, 문맥에 따른 '의미 판별(Sense Disambiguation)'뿐이다"**라는 문제 정의에서 출발합니다.

##### 1) 문제의 본질: 생성이 아닌 '문맥적 분류(Classification)'
텍스트 정규화(TN)와 음운 변환(G2P)은 원문의 문장 구조와 단어 배치를 그대로 보존해야 하는 태스크입니다. 여기서 발생하는 모호성은 오직 특정 어휘나 수사, 기호가 문맥상 **'어떤 의미 범주(Semantic Class)로 쓰였는가'**를 식별하는 **어휘 의미 변별(Word Sense Disambiguation, WSD)**의 문제입니다.
따라서 토큰을 하나씩 순차적으로 생성하며 불필요한 연산 오버헤드와 단어 왜곡 위험을 초래하는 자기회귀적(Autoregressive) 생성형 모델(GPT 계열, Seq2Seq 디코더)은 본 태스크에 과도한 비용을 발생시키며 목적에 부합하지 않습니다. 오직 문장의 문맥을 깊이 있게 이해하고 압축하는 **'인코더(Encoder)'**만으로도 충분합니다.

##### 2) BERT와 프로빙(Probing) 이론의 최적성
SNAP이 백본으로 BERT(Bidirectional Encoder Representations from Transformers)를 선택한 이론적 근거는 다음과 같습니다:
* **양방향 문맥 참조 (Bidirectional Contextualization)**: 단어의 발음은 앞선 단어뿐만 아니라 뒤따르는 조사, 단위명사, 서술어에 의해 결정되는 경우가 많습니다. 타겟 단어의 전후방 문맥을 동시에 셀프 어텐션(Self-Attention)으로 조망하는 BERT의 양방향 구조는 발음 모호성 해소에 적합한 수학적 표상을 제공합니다.
* **표상 프로빙(Representation Probing) 이론**: 자연어 처리 표상 분석 연구(Tenney et al., 2019; Hewitt & Liang, 2019)에 따르면, 사전학습된 BERT 인코더의 은닉층(Hidden States)은 형태소와 구문뿐만 아니라 고차원의 어휘적 의미(Word Sense)를 이미 고밀도 기하학적 공간에 충분히 내재화하고 있음이 입증되었습니다.
* **단일 순방향 패스(Single Forward Pass) 기반 저지연 추론**: 인코더의 은닉 벡터 위에 1계층 경량 선형 분류기(**Span-Level Probing Head**)만 결합하면, 복잡한 디코딩 과정 없이 단 한 번의 비자기회귀적(Non-autoregressive) 추론만으로 모호한 어휘의 의미 태그를 마이크로초(µs) 단위로 정확히 추출할 수 있습니다.

##### 3) 신경망과 결정론적 룰 엔진의 엄격한 역할 분담
* **신경망의 책임 = '문맥 정보 제공자' (Span-Level Probing Head)**:
  * 신경망은 텍스트를 직접 생성하거나 발음열을 조작하지 않습니다.
  * 동결된 경량 BERT 백본 위에서 가볍게 동작하는 Probing Head가 **문맥 의존성이 높은 특정 어휘·수사·기호의 의미적 속성(Span Tag/품사)만 마이크로초 단위로 판별하여 룰 엔진에 전달**합니다.
* **룰 엔진의 책임 = '최종 발음 판별 및 변환' (100% Deterministic Rule Engine)**:
  * 신경망이 제공한 의미 태그 정보를 바탕으로, **실제 텍스트 치환과 국립국어원 표준 발음법(연음, 자음동화, 경음화 등) 적용은 엄격히 검증된 네이티브 룰 엔진이 100% 결정론적으로 수행**합니다.
  * 이를 통해 신경망의 텍스트 왜곡 위험을 줄이고 출력의 일관성을 유지하며, 예외 상황 발생 시 사용자 정의 사전이나 룰 수정을 통해 즉각 제어할 수 있습니다.
* **유연한 배포 모드**:
  * **단독 구동 모드 (Standalone Mode)**: 약 50~60MB의 메모리 점유율과 수 ms 수준의 빠른 처리 속도로 독립 TTS 파이프라인의 실시간 연동에 충분한 성능을 제공합니다.
  * **BERT 내장형 TTS 연동 (Embedded Mode, 특수 케이스)**: MeloTTS, BERT-VITS2처럼 음향 모델 자체가 운율 예측을 위해 이미 내부에서 BERT를 구동하는 아키텍처 군의 경우, 해당 모델의 계산된 BERT Hidden States를 공유·재사용함으로써 전처리로 인한 추가 연산 오버헤드를 거의 발생시키지 않고(Near-Zero) 처리할 수 있습니다.

### 1.2. SNAP v1.0에서의 성과

SNAP v1.0은 BERT 모델을 이용하여 한국어·일본어·영어를 아우르는 **'Pure Context Probing'** 아키텍처를 확립하였고, 대형 언어 모델(LLM)의 연산 부하를 배제하면서도 규칙 기반 엔진의 한계였던 문맥성 모호성을 상당히 해결했습니다. v1.0 연구 개발을 통해 실증된 핵심 기술적 성과는 다음과 같습니다:

* **다국어 프론트엔드 프로빙 개념 증명 (Proof of Concept)**:
  * 한국어의 수사 체계(고유어 vs 한자어) 및 동철이음이의어(경음화 여부), 일본어의 한자 독음(음독 vs 훈독 vs 숙자훈), 영어의 품사/시제별 동철이음어(Heteronym) 등 주요 3대 언어의 대표적 발음 모호성 문제들을 **동결된 소형 BERT 표상에 부착된 1-Layer 경량 Probing Head만으로 높은 정확도로 판별할 수 있음**을 체계적으로 입증하였습니다.
* **고전적 형태소 분석기의 완전한 대체 (한국어·일본어 Morph Head)**:
  * 교착어인 한국어와 띄어쓰기가 없는 일본어에서 지난 수십 년간 필수적인 블랙박스로 여겨졌던 고전 형태소 분석기(MeCab, MeCab-ko, Sudachi 등)의 구조적 한계—노후화된 사전으로 인한 신조어 인식 실패, 통계적 Viterbi 오류의 불투명성, 외부 C 라이브러리 의존성—를 전면 극복하였습니다.
  * 정적 사전 룩업(Trie) 피처와 BERT 은닉 벡터를 결합한 **자체 'Morph Head'를 구축하여 문자 단위 BIO-POS 태깅을 수행함으로써, 외부 형태소 분석기 없이도 신조어와 복합어의 형태소 경계 및 품사를 훨씬 정밀하고 유연하게 추출하는 데 성공**하였습니다.
* **'단일 인코더 + 멀티 프로빙 헤드' 아키텍처의 유효성 실증**:
  * 여러 파편화 도구나 무거운 모델 없이, **단일 BERT 백본 위에 전용 Probing Head(Morph, Counter, Heteronym, Semiotic)들을 결합한 구조로 프론트엔드 태스크를 효과적으로 수행할 수 있음**을 실증하였습니다.
* **최신 오픈소스 음향 모델과의 실증 연동**:
  * MeloTTS, Piper, F5-TTS 등 최신 음향 모델 파이프라인과 결합하여, 사람이 수작업으로 사전 대본을 수정(오버라이딩)하거나 발음열을 손보지 않아도 최종 합성 음성의 발음 명료도와 자연스러움이 비약적으로 향상됨을 검증하였습니다.

### 1.3. SNAP v2.0 프로덕션 엔진으로의 진화

SNAP 한국어 v2.0은 v1.0의 원천 하이브리드 연구 성과를 실제 상용 음성합성 및 대화형 AI 파이프라인에 안정적으로 탑재할 수 있도록, **프로덕션 환경이 요구하는 처리 속도, 자원 효율성, 어문 규범의 완성도**를 확보하기 위해 전면적인 고도화를 단행했습니다:

* **백본 경량화 및 지식 증류 (Knowledge Distillation)**:
  * v1.0에서는 12-Layer Base BERT(INT8 ONNX)를 백본으로 사용하였으나, 교사 모델의 문맥 표현력을 소형 학생 모델로 전이하는 지식 증류 기법을 적용하였습니다.
  * 그 결과, 파라미터와 연산량을 대폭 압축한 **3-Layer 및 4-Layer Mini BERT 모델만으로도 기존 12-Layer 모델과 거의 동일한 수준의 문맥 변별 성능**을 확보하였으며, 모델 파일 용량을 절반 수준(54MB)으로 줄이고 백본 추론 속도를 약 3배 가속하였습니다.
* **BERT Probing 구조 변경 (독립형 서브헤드 분할 및 On-demand 추론)**:
  * v1.0에서는 동철이음이의어(Heteronym)처럼 단일 헤드 내에 여러 어휘의 클래스를 묶어 통합 추론했으나, 언어학적으로 서로 완전히 독립된 어휘들이 가중치를 공유하면서 학습 및 추론 시 다른 클래스의 결정 경계에 부정적인 간섭(Interference)을 주는 문제가 있었습니다.
  * v2.0에서는 이를 전면 개편하여, 각 어휘 및 태스크별로 완전히 분리된 **초경량 독립 전용 서브헤드(Decoupled Independent Sub-heads)** 구조로 재설계하였습니다.
  * 아울러 문장 내에 해당 타겟 어휘나 기호가 실제로 출현했을 때만 해당 헤드를 호출하는 **On-demand(조건부) 추론 방식**을 적용하여, 클래스 간 간섭을 줄이고 불필요한 연산을 방지하였습니다.
* **프로덕션 환경을 위한 네이티브 파이프라인 최적화**:
  * Python 중심의 프로토타입 파이프라인에서 벗어나 전체 런타임을 **C++17 네이티브 엔진**으로 재구축하였습니다.
  * 런타임 연산 병목을 제거하기 위해 **사전 할당 버퍼 풀링**, 백트래킹 오버헤드가 없는 **단일 패스 비트마스크/LUT 음운 스캐너**, 재귀 오버헤드를 배제한 **1차원 Flat DP(Viterbi 방식) 경로 탐색** 등 프로덕션 레벨의 최적화를 적용하여, 범용 CPU 환경에서도 수 ms 수준으로 처리하여 실시간 연동에 충분한 성능을 확보하였습니다.
* **현대 한국어 발음법의 정밀한 이식 (표준 발음법 30개 전수 구현)**:
  * 국립국어원 『표준 발음법』 제1항부터 제30항까지의 전 조항(받침의 발음, 자음동화, 경음화, 사잇소리 현상 등)을 규칙 엔진에 체계적으로 구현하였습니다.
  * 특히 단순 규칙으로 풀기 힘든 한자어 'ㄹ' 뒤 경음화(제26항), 용언 어간 뒤 경음화(제24항), 복합어 사잇소리(제30항) 등 문맥·품사 의존적 음운 변동을 Probing Head와 연동하여 정밀 처리하며, 10,000문장 자체 구성 골든 베이스라인 전수 검증을 통해 규범적 완성도를 확보하였습니다.
* **다양한 도메인 활용을 위한 유연한 제어 옵션**:
  * AI 음성 비서, AICC, 오디오북 낭독, 내비게이션 등 서비스 목적과 도메인에 맞춤화할 수 있는 실용적인 옵션들을 기본 탑재하였습니다:
    - **대화체 문체 변환 (`speech_style`)**: 문어체 문장을 대화형 음성 서비스에 최적화된 구어체(해요체/하십시오체)로 자동 변환
    - **모음 장단음 제어 (`vowel_length`)**: 아나운서 낭독 수준의 장음 음절 식별 및 W3C SSML prosody 태그 연동
    - **발음 스타일 모드 (`pronunciation_style`)**: 엄격한 표준 발음 외에도 일상 대화 관용음이나 현실 발음 선택 지원
    - **동적 커스텀 사전 (`custom_dict`)**: 서비스 운영 중 신조어나 고유명사 오독을 무중단으로 즉각 교정할 수 있는 핫픽스 지원

## 2. 핵심 아키텍처: 하이브리드 파이프라인 & 경량 백본

### 2.1. 하이브리드 파이프라인 전체 구조

SNAP v2.0 파이프라인은 텍스트가 유입되는 순간부터 최종 발음열과 운율 태그가 출력되기까지 정밀하게 분업화된 구조로 동작합니다:

```
[입력 텍스트 원문 (UTF-8)]
          │
          ▼
┌────────────────────────────────────────────────────────┐
│  C++ Native Single-Pass LUT/Bitmask Scanner            │
│  - 특수 기호, 숫자 서식, 영단어, 복합 모델명 1차 스캔   │
└────────────────────────────────────────────────────────┘
          │
          ▼
┌────────────────────────────────────────────────────────┐
│  Distilled Mini BERT Backbone (3L / 4L, INT8 Quantized)│
│  - ONNX Runtime Zero-Copy 텐서 바인딩                  │
│  - 단일 순방향 패스로 고차원 문맥 벡터(Hidden State) 추출│
└────────────────────────────────────────────────────────┘
          │
          ├─► ① Counter Head   : 수사/단위명사 문맥 분류 (고유어 vs 한자어)
          ├─► ② Heteronym Head : 9대 핵심 동철이음이의어 어휘 문맥 변별
          ├─► ③ Semiotic Head  : 특수기호/서식 문맥 구어화 판별
          └─► ④ Morph Head     : 문맥 기반 품사 태깅 및 형태소 경계 감지
          │
          ▼
┌────────────────────────────────────────────────────────┐
│  C++ Deterministic Phonology Engine                    │
│  - 1차원 Flat DP (Viterbi) 형태소 결합 경로 탐색       │
│  - 국립국어원 표준 발음법 30개 전수 조항 규칙 테이블   │
│  - 고속 비트마스크 음운 자질 연산 (Look-up Table)     │
└────────────────────────────────────────────────────────┘
          │
          ▼
[정규화 텍스트 / 표준 G2P 발음열 / 운율 끊어읽기 태그 / SSML]
```

### 2.2. 지식 증류(Knowledge Distillation) 기반 경량 백본 (12L → 4L/3L)

실시간 처리에 적합한 경량 파이프라인을 구축하기 위해, SNAP v2.0은 교사 모델(12-Layer Base BERT)의 문맥 표상 능력을 학생 모델(4-Layer 및 3-Layer BERT)로 전이하는 **지식 증류(Knowledge Distillation)** 파이프라인을 구축하였습니다.

* **증류 파이프라인 구조**:
  1. **Logit Distillation**: 교사 모델의 Softmax 출력 분포와 학생 모델의 분포 사이의 Kullback-Leibler(KL) 발산을 최소화.
  2. **Hidden State Alignment**: 트랜스포머 특정 레이어 간의 표현 벡터를 매핑하여 중간 문맥 특징 손실을 억제.
  3. **Task-Specific Head Fine-Tuning**: 증류된 백본 위에 각 Probing Head를 연결하고 정밀 레이블 데이터셋을 바탕으로 엔드투엔드 미세조정.

* **모델 크기 및 레이어 경량화 성과**:
  * **12-Layer (Base Baseline)**: 약 115 MB
  * **4-Layer (KD 12to4)**: 약 61 MB (모델 크기 절반 수준 감축 및 고속화)
  * **3-Layer (KD 12to3)**: 약 54 MB (초경량 크기 및 빠른 추론 속도)

이러한 경량화를 통해 모델 용량을 절반 수준으로 줄이면서도, CPU 환경에서 백본 추론을 빠르게 처리할 수 있는 효율성을 확보했습니다.

## 3. 한국어 발음 변환 및 음운 처리 체계

SNAP 한국어 v2.0의 조항별 세부 규칙과 변환 예례는 [SNAP 한국어 v2.0 세부 기능 명세서](SNAP_KO_v2.0_FUNCTIONAL_SPEC.md)에 상세히 정의되어 있습니다.

본 엔진은 음성합성 및 대화형 AI 환경에서 높은 발음 변환 정확도와 자연성을 확보하기 위해 다음과 같은 다층적 음운·언어 처리 체계를 통합 지원합니다:

1. **표준 발음 규범 베이스라인 구축**:
   * 국립국어원 『표준 발음법』 7개 장 30개 전 조항(받침 평폐쇄음화, 자음동화, 구개음화 등)을 기본 규칙 엔진에 전수 구현하여 어문 규범에 부합하는 안정적인 기초 발음열을 확정합니다.
2. **문맥 및 품사 기반 핵심 음운 변동 정밀 해결**:
   * 단순 문자열 치환만으로는 오독을 피하기 어려운 한자어 'ㄹ' 뒤 경음화(제26항: *갈등[갈뜽]* vs *발달[발달]*), 용언 어간 받침 뒤 경음화(제24항: *신고[신꼬]* vs *신고식[신고식]*), 관형사형 어미(제27항), 동철이음이의어(Heteronym: *대가, 물가*), 복합어 사잇소리 현상 등을 신경망 Probing Head의 품사 및 문맥 태깅과 연동하여 정밀하게 분별합니다.
3. **실무 환경 외래어 및 서식 텍스트 구어화**:
   * 사전에 등록되지 않은 미등록 영단어(OOV)의 자체 음절 분절 한글화(*CloudNative* [클라우드네이티브]), 복합 IT 제품 모델명 독음 추출(*iPhone 16 Pro* [아이폰 십육 프로]), 일상 대화 관용 발음(*버스* [뻐스], *효과* [효꽈])을 자연스럽게 변환합니다.
   * 통화·물리 단위(100여 종), 날짜·시각, 분수, 전화번호, 특수기호 등 다양한 수치·서식을 문맥에 맞는 자연스러운 구어 형태로 정규화합니다.
4. **서비스 목적별 대화체 문체 및 운율 제어**:
   * 챗봇 및 대화형 음성 서비스를 위한 문어체 종결어미의 구어체 자동 변환(`haeyo` 해요체 / `hapsio` 하십시오체), 아나운서 낭독 수준의 모음 장단음 운율 제어(`vowel_length`), 긴급 오독 교정을 위한 무중단 커스텀 사전(`custom_dict`)을 제공합니다.

이와 같이 기본 규범 규칙을 탄탄한 베이스라인으로 삼고, 문맥 의존적 음운 변동과 실무 도메인 서식을 통합 처리함으로써 높은 발음 변환 정확도를 실현하였습니다.

#### 📊 핵심 Probing Head 범주별 정량 벤치마크 정확도

품사(POS) 정보만으로 구분이 가능한 동철이음어는 Morph Head의 158개 세부/복합 품사(BIO-POS) 태깅과 룰 엔진을 통해 추가 연산 없이 처리되며, 둘 다 동일한 품사(명사)여서 형태소 정보만으로는 구별할 수 없는 고난도 어휘 및 수량·서식 영역은 전용 Probing Head가 전담합니다. 핵심 Probing Head 범주별 골든셋 실측 정확도는 다음과 같습니다:

| Head 범주 (Category) | 주요 해결 과제 및 대상 | 검증 데이터 규모 | 실측 정확도 | 평가 및 성능 분석 |
| :--- | :--- | :---: | :---: | :--- |
| **Counter Head** | 8대 단위(대, 번, 장, 기 등) 수사 분류 (고유어 vs 한자어) | 6,959건 전수 | **`99.76%`** | 12L Teacher(99.65%) 대비 동등 수준 정확도 달성 |
| **Semiotic Head** | 특수기호(`:`, `/`, `~` 등) 8대 서식 문맥 구어화 | 2,151건 | **`99.40%`** | 시간, 날짜, 비율, 점수 등 문맥별 구어화 지원 |
| **Heteronym Head** | 품사(POS)가 동일하여 형태소 분석만으로 변별 불가한 9대 핵심 동철이음이의어 (`대가`, `시가`, `잠자리` 등) | 1,943건 | **`93.40%`** | 독립 서브헤드 분할로 클래스 간 상호 간섭 최소화 |
| **Morph Head** | 문맥 기반 158개 세부/복합 품사(BIO-POS) 태깅 및 형태소 경계 감지 | 국립국어원 형태 분석 최신 말뭉치(NIKL_MP 2025 구어·문어) 12,432문장 (24.3만자) | **`93.98%`** | 자모 단위 2D DP 정밀 정제셋 전수 검증 |

> **💡 Morph Head 오차 분석 및 실질 발음 영향**:  
> **국립국어원 형태 분석 말뭉치 2025 최신판(NIKL_MP 2025 구어·문어 통합본)** 기준 실측 오차(6.02%) 중 **대부분(약 4.5%)은 고유명사↔일반명사 혼동 등 발음에 영향이 없거나 외래어/고유명사 사전으로 100% 후보정**되는 영역입니다. 연음·경음화에 실질적 영향을 미칠 수 있는 용언↔체언(`VV↔NNG`) 품사 혼동은 전체 음절의 **약 0.48%**에 불과하며, 이 역시 C++ 1D Flat DP 음운 룰 엔진을 거치며 보정될 가능성이 높습니다.

## 5. 프로덕션 통합 및 실시간 파이프라인 연동

### 5.1. REST API 및 실시간 스트리밍 구조

SNAP v2.0은 현대적인 마이크로서비스 아키텍처(MSA) 및 클라우드 환경과의 유연한 통합을 위해 **실시간 REST API를 표준 TTS 연동 인터페이스**로 채택하였습니다:

* **표준 인터페이스 및 엔드포인트**:
  - 단일 발화 실시간 전처리: `POST /v1/normalize`
  - 대용량 텍스트 일괄 처리: `POST /v1/normalize/batch` (**배치 처리 기본 지원**)
* **다양한 운영 옵션 제어**: 문체 변환(`speech_style`), 발음 규범 모드(`pronunciation_style`), 운율 쉼표 태깅(`prosody_format`), 장단음 제어(`vowel_length`), IPA 기호 변환(`return_ipa`) 등 도메인별 세부 설정을 요청 파라미터(`config`)로 손쉽게 지정할 수 있습니다.
* **컨테이너 기반 배포 (Docker Container)**:
  - **오픈 테스트 API 운영**: 현재 개발자와 연구자가 즉시 연동 규격을 검증하고 품질을 테스트할 수 있도록 SNAP 공식 Docker 컨테이너 기반의 라이브 테스트 API를 오픈 운영하고 있습니다.
  - **로컬망/폐쇄망 독립 설치 지원**: 외부 인터넷 연결이 차단된 금융권, 공공기관 및 기업 사내망 환경에서도 제공되는 Docker 컨테이너 이미지를 반입·설치하여 자체 독립 전처리 인프라로 손쉽게 적용할 수 있습니다.

* **단일 요청 및 응답 예시**:
```json
{
  "text": "오늘 회의 결과 3분기 매출이 150억 원 증가했습니다.",
  "config": {
    "speech_style": "haeyo",
    "pronunciation_style": "modern_standard",
    "prosody_format": "tags",
    "return_ipa": false
  }
}
```
```json
{
  "success": true,
  "data": {
```

### 5.2. C/C++ Native SDK 및 ABI 인터페이스

네트워크 레이어의 오버헤드를 허용하지 않는 고성능 온프레미스(On-premise) 환경 및 임베디드 디바이스 지원을 위해, SNAP v1.0에서 표준이었던 **공유 라이브러리(Shared Library: `snap_cpp.dll` / `libsnap_cpp.so`) 네이티브 연동 방안** 역시 지속 제공합니다.

C ABI 호환성을 갖춘 모든 프로그래밍 언어(C++, Rust, Go, C#, Java, Swift 등)에서 프로세스 내(In-Process)에 직접 바인딩하여 추가적인 통신 오버헤드 없이 수 마이크로초 단위의 무오버헤드 호출을 수행할 수 있습니다:

```c
#include "snap_api.h"
#include <stdio.h>

int main() {
    // 1. SNAP 엔진 인스턴스 초기화 (모델 가중치 경로 및 언어 코드)
    void* handle = snap_create("./models/ko", "ko");
    if (!handle) {
        fprintf(stderr, "SNAP 엔진 초기화 실패\n");
        return -1;
    }

    // 2. 텍스트 전처리 및 문맥 발음 변환 수행 (단일 호출)
    const char* result_json = snap_process(handle, "3번 버스가 10분 뒤 도착합니다.");
    if (result_json) {
        // 결과 JSON 참조: {"normalized_text": "...", "phonology": "...", ...}
        printf("전처리 결과: %s\n", result_json);

        // 3. 반환된 문자열 버퍼 해제 (필수)
        snap_free((void*)result_json);
    }

    // 4. 동적 옵션(대화체 어미 변환 등) 적용 시: snap_process_ext 활용
    const char* ext_result = snap_process_ext(handle, "오늘 회의 결과가 나왔습니다.", 
                                              "{\"speech_style\": \"haeyo\"}");
    if (ext_result) {
        printf("옵션 적용 결과: %s\n", ext_result);
        snap_free((void*)ext_result);
    }

    // 5. 엔진 인스턴스 자원 반환
    snap_destroy(handle);
    return 0;
}
```

### 5.3. 최신 음향 모델(MeloTTS, Piper, F5-TTS) 연동 파이프라인

```
         └─► F5-TTS / CosyVoice 연동 : 비정형 구어체 정제 및 숫자 한글화
```

### 5.4. 동적 사용자 커스텀 사전(`custom_dict`) 무중단 핫픽스

서비스 운영 중 발생하는 긴급한 브랜드명, 인명, 신규 약어의 오독을 서버 재시작이나 모델 재학습 없이 즉각 교정할 수 있는 `custom_dict` 동적 매핑 기능을 제공합니다:

```json
{
  "대화형AI": "대화형 에이아이",
  "LLM": "엘엘엠",
  "AICC": "에이아이씨씨"
}
```
C++ 엔진 내부의 원자적 포인터 교체(Atomic Pointer Swap)를 통해 서비스 무중단 상태에서 1ms 이내로 실시간 반영됩니다.

## 6. 결론 및 향후 전망

**SNAP 한국어 v2.0**은 음성합성 및 대화형 AI 프론트엔드가 요구하는 **표준 규범 준수**, **실시간 처리 속도**, **문맥에 따른 발음 변별력**을 단일 네이티브 엔진으로 구현한 텍스트 전처리 시스템입니다.

SNAP은 다음과 같은 아키텍처적 특징을 중심으로 구성되었습니다:

1. **결정론적-신경망 하이브리드 아키텍처 (Deterministic-Neural Hybrid Architecture)**: 모호 어휘의 문맥 의미 분류는 경량 신경망이 수행하고, 실제 음운 규칙 및 수사 변환은 결정론적 C++ 엔진이 전담하여 예측 가능하고 일관된 변환 결과를 제공합니다.
2. **비자기회귀 문맥 프로빙 (Non-Autoregressive Context Probing)**: 토큰을 순차 생성하는 디코더 없이, 경량 인코더의 단일 순방향 패스(Single Forward Pass)로 모호 어휘의 문맥적 속성을 빠르게 분류합니다.
3. **조건부 독립 서브헤드 체계 (On-Demand Decoupled Sub-Heads)**: 개별 모호 어휘군별로 독립된 서브헤드를 구성하여 어휘 간 간섭을 줄이고, 해당 어휘가 텍스트에 나타났을 때만 추론을 수행하여 불필요한 연산을 줄였습니다.
4. **네이티브 최적화 및 다양한 연동 인터페이스**: C++ 네이티브 엔진 최적화를 통해 범용 CPU 환경에서도 수 ms 수준으로 처리하여 실시간 연동에 충분한 성능을 확보하였으며, REST API, Docker 컨테이너, C ABI 연동 및 동적 사용자 사전 수정을 지원합니다.

향후에는 일본어 및 영어 엔진과의 다국어 파이프라인 통합과 온디바이스 NPU 가속 백엔드 지원을 지속적으로 진행할 예정입니다.
